# Choisir la stack de mon ERP — méthode des grandes entreprises

> **Artefact principal (interactif) : ouvrez `index.html`** — questionnaire complet avec sauvegarde
> automatique, recommandation en direct et export. Ce fichier est la version texte, remplissable
> à la main si vous préférez. Vos réponses finales vivent dans **`decisions/mes-choix.json`**.

## 1. Ce que font les grandes entreprises (synthèse de la recherche)

Elles ne choisissent pas « la techno à la mode », elles remplissent une **matrice de décision pondérée** :

| Critère | Poids type | Question à se poser |
|---|---|---|
| Adéquation au besoin métier | ~30 % | La techno couvre-t-elle mes modules ERP sans contorsion ? |
| Scalabilité (3–5 ans) | ~25 % | Tient-elle ×10 en utilisateurs/données sans réécriture ? |
| Équipe & recrutement | ~25 % | Ai-je / trouverai-je des gens qui savent la coder ? |
| Sécurité & conformité | ~20 % | RGPD, rôles, audit, sauvegardes sont-ils natifs/aisés ? |
| TCO (coût total sur 3 ans) | ~20 % | Licences + hébergement + maintenance + salaires, pas juste le prix d'appel |
| Écosystème & intégrations | ~18 % | Communauté, bibliothèques, API, connecteurs existants |

Principes qui reviennent partout :

- **« Boring technology »** : technos matures et massivement adoptées (PostgreSQL = base n°1 mondiale,
  58,2 % des développeurs en 2025 ; React 47 % et Node.js 49 % en tête des frameworks — Stack Overflow Survey 2025).
- **Monolithe modulaire d'abord, microservices ensuite** : les ERP historiques (SAP & co) migrent
  progressivement (pattern *Strangler Fig*). Démarrer en microservices avec une petite équipe est l'erreur classique.
- **API-first** : un ERP vit connecté (banque, e-commerce, compta, e-mail).
- **Sécurité dès le jour 1** : rôles/permissions, journal d'audit, sauvegardes — non négociables sur des données paie/finance.
- **Décision écrite** (ADR) : chaque choix est daté, justifié, versionné dans Git → c'est le rôle de `decisions/`.

Sources : BEON (matrice CTO 30/25/25/20), Nerdify (piliers & TCO), CISIN (framework ERP en 5 piliers),
Stack Overflow Developer Survey 2025, msg advisors (ERP & microservices), Axis Intelligence (critères Fortune 500).

## 3. Comment je stocke et j'utilise vos réponses

1. Vous répondez dans `index.html` → sauvegarde auto dans le navigateur.
2. Vous cliquez **Exporter JSON** → `mes-choix.json`, et vous me le donnez (ou collez le résumé Markdown dans le chat).
3. Je l'enregistre dans **`decisions/mes-choix.json`** (versionné Git, daté) + un résumé dans `decisions/README.md`.
4. Avant chaque développement, je relis ce fichier : **vos choix explicites priment sur mes recommandations**.

Recommandation par défaut si vous répondez « décide pour moi » partout (profil PME, petite équipe) :
**monolithe modulaire · React + TypeScript · Node.js + TypeScript (ou Python si c'est votre compétence) ·
PostgreSQL · Docker · hébergement européen simple ou cloud majeur · rôles + audit + sauvegardes dès la v1.**
